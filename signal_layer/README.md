The `signal_layer` is the online signal extraction component of HTM. It uses a small instruction-following language model (≈1.5B parameters) to produce the six trajectory signals consumed by the trust layer. Rather than training model weights, HTM optimizes the scoring prompt using **GEPA**, allowing the student model to approximate the teacher's trajectory-level annotations while keeping inference fast.

The trust layer is **not** optimized: GEPA evolves only the signal prompt, with the frozen HTM controller included in the optimization objective.

## Directory structure

| Path | Purpose |
|------|---------|
| `config/` | Configuration for models, GEPA optimization, and evaluation. |
| `prompts/` | Seed and GEPA-optimized prompts used by the signal model. |
| `data.py` | Loads processed datasets and manages train/validation/test splits. |
| `scorer.py` | Signal extraction model and per-turn inference pipeline. |
| `objective.py` | GEPA optimization objective (detection + teacher agreement). |
| `pipeline.py` | Runs prompt optimization and manages checkpoints. |
| `evals/` | Offline evaluation, metrics, baselines, and comparison utilities. |
| `optimize/` | Experimental optimization of HTM trust dynamics. |
| `main.py` | CLI entry point. |

## Pipeline

The signal layer consists of two models:

- **Student model** – A small instruction-following LLM that runs online and predicts the six HTM signals for each conversation turn.
- **Reflection model** – A larger LLM used only during GEPA optimization to iteratively improve the student prompt. It is never used at inference time.

GEPA optimizes the prompt against two objectives:

- **Detection:** trajectory-level performance using the frozen HTM trust controller.
- **Teacher agreement:** agreement with cached trajectory-level labels generated by the offline teacher.

Since teacher labels are generated beforehand, optimization only requires reflection-model API calls.

## Evaluation

Evaluation is model agnostic. Each run stores the complete per-turn signal matrix together with the resulting trust, control, and action trajectories. Saved runs can later be compared offline without rerunning any models.

Reported metrics include:

- AUROC
- TPR at matched FPR
- Teacher agreement
- Mean lead time before the payload turn
- Inference latency
- Per-dataset performance

## Quickstart

```bash
pip install -e ".[gepa]"

# Optimize the signal prompt
python -m signal_layer.main --stage optimize

# Inspect one conversation
python -m signal_layer.main --stage inspect --dataset sharegpt

# Evaluate a detector
python -m signal_layer.main --stage eval --name gepa

# Compare saved evaluation runs
python -m signal_layer.main --stage compare
```

## Design principles

- The trust controller remains frozen during prompt optimization.
- Signal semantics and the six-signal interface are fixed.
- Only structured JSON signal outputs are produced.
- The signal model uses the current turn together with the HTM trust state as its only memory.
- All optimization checkpoints are saved so interrupted GEPA runs can be resumed.
